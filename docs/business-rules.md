# 업무 규칙

## 사람·부서·역할

- 역할은 세 가지다: 신청자(일반 사용자), 자산담당자, 관리자. 자산담당자와 관리자는 신청자 권한을 함께 가진다. 관리자는 입고·지급·재고·자산 관리를 하지 않는다.
- **부서장**은 역할이 아니라 부서별 지정이다. 부서마다 최대 1명, 그 부서 소속 업무사용자 중에서 관리자가 지정한다. 이미 지정된 부서에 다시 지정하면 교체된다.
- **로그인 가능한 계정** = 업무사용자 상태가 승인(`P`)이고, 잠금 표시가 없고, 권한 행이 있는 계정.
  - 잠김: 잠금 표시만 켜진 상태(로그인 5회 연속 실패 포함).
  - 비활성: 잠금 표시 + 권한 행 제거.
  - 둘 다 로그인할 수 없다.
- **부서장 유효 조건**: 지정된 사람이 지금도 그 부서 소속이고 로그인 가능한 계정일 때만 부서장으로 본다. 부서를 옮겼거나 잠김·비활성·미승인이면 그 부서는 부서장이 없는 것으로 본다. 지정 기록은 자동으로 지우지 않으며, 지정 화면에 '무효'와 이유(이동/잠김/비활성/권한 없음/계정 없음)를 보여 준다.
- 신청은 부서가 지정된 업무사용자만 한다. 일반·기업 회원 계정은 신청할 수 없다.

## 품목

- 유형: 수량 비품(`QTY`, 기관 전체 재고 수량 하나) / 개별 자산(`UNIT`, 자산번호로 한 대씩).
- 품목코드는 시스템이 만들고 바뀌지 않는다. 새 품목의 재고·확보 수량은 0이며, 품목 등록 화면에서 재고를 넣을 수 없다.
- 품목명은 **사용 중인 품목끼리** 중복될 수 없다. 사용 중지한 품목의 이름은 새 품목이 쓸 수 있다. 사용 중지 품목을 되살릴 때 같은 이름의 사용 중 품목이 있으면 거부한다.
- 유형은 이력(재고 변동 이력, 신청 품목, 개별 자산 중 하나라도)이 생기면 바꿀 수 없다.
- 삭제는 이력이 전혀 없을 때만 된다. 이력이 있으면 삭제를 막고 사용 중지를 안내한다.
- 사용 중지 품목은 새 신청·자산 등록·일괄등록에서 빠진다. 이미 제출된 신청(대기·승인)은 그 품목이어도 승인·지급·취소를 끝까지 처리한다.
- 최소 수량(0 이상, 기본 0)은 야간 부족 집계 기준이다.

## 가용 수량(모든 재고 판단의 기준)

- 수량 비품: `가용 = 재고 수량`. 재고는 승인 때 이미 줄어 있다.
- 개별 자산: `가용 = 보관 상태 자산 수 − 확보 수량`. 사용·수리·폐기 자산은 보관 수에 들지 않는다.
- 확보 수량(개별 자산만)은 항상 "'승인' 상태 신청서들의 그 품목 승인 수량 합"과 같다. 승인하면 늘고, 지급하면 지급한 대수만큼 줄고, 지급취소하면 승인 수량만큼 줄어든다.
- 재고·확보·가용 중 하나라도 0 미만이 되는 처리는 거부하고 아무것도 바꾸지 않는다.

## 재고 변동과 이력(수량 기준)

모든 변동은 재고 이력 한 행을 남긴다: 품목, 유형, 증감, 변동 후 값, 사유, 관련 신청서, 처리자, 처리 시각.

| 유형 | 언제 | 수량 비품 | 개별 자산 |
|---|---|---|---|
| `IN` 입고 | 담당자 입고(1 이상) / 자산 1대 등록 | 재고 +n, 변동 후=재고 | 가용 +1, 변동 후=가용 |
| `ADJUST` 조정 | 담당자, 사유 필수, 증감 ≠ 0 | 재고 ±n, 결과 < 0이면 거부 | 없음(개별 자산은 조정·입고 수량 입력 불가, 등록으로만 는다) |
| `RESERVE` 승인 확보 | 승인 | 재고 −n | 확보 +n → 가용 −n |
| `RELEASE` 지급 취소 복구 | 지급취소 | 재고 +n | 확보 −n → 가용 +n |
| `DELIVER` 지급 | 지급(개별 자산만) | (행 없음 — 수량 비품은 지급 때 변화 없음) | 보관 −n, 확보 −n → 가용 변화 0, 증감 0 |

- 반납·수리·수리 완료·폐기는 재고 이력을 남기지 않는다(유형이 없다). 그 기록은 자산 이력이다.
- 재고 이력 화면은 `RELEASE`를 "지급 취소 복구"로 표시한다.

## 개별 자산

- 자산번호는 담당자가 입력하며 **폐기된 자산을 포함해 시스템 전체에서** 중복될 수 없다(대소문자만 다른 번호도 중복으로 본다 — DB 기본 collation).
- 등록 = 입고 1건: 보관 상태로 만들고, 자산 이력 첫 행(이전 상태 없음 → 보관)과 재고 이력 `IN` +1을 남긴다. 사용 중인 개별 자산 유형 품목에만 등록한다.
- 상태 전이(표에 없는 전이는 모두 거부):

| 전이 | 조건 |
|---|---|
| 보관 → 사용 | 지급 처리 안에서만. 현재 사용자 = 신청자 |
| 사용 → 보관(반납) | 현재 사용자를 비운다 |
| 보관 → 수리 | 전이 후 `보관 수 − 1 ≥ 확보 수량`일 때만 |
| 수리 → 보관(수리 완료) | 항상 |
| 보관 → 폐기 | 사유 필수, 전이 후 `보관 수 − 1 ≥ 확보 수량`일 때만 |
| 수리 → 폐기 | 사유 필수, 항상 |

- 사용 중 자산은 수리·폐기할 수 없다(먼저 반납). 분실·파손은 폐기 + 사유로 처리한다. 폐기는 끝 상태이며 기록은 지우지 않는다.
- 모든 전이는 자산 이력(이전·이후 상태, 사유, 관련 신청서, 처리자, 시각)을 남긴다.

## 신청서

- 헤더(신청번호, 신청자, **신청 당시 부서**, 신청 사유(선택, 1000자 이내), 상태, 신청 시각) + 신청 품목 1개 이상(품목, 신청 수량 ≥ 1, 승인 수량, 결과, 반려 사유).
- 같은 품목을 여러 줄에 적으면 한 줄로 합친다(수량 합산). 품목과 수량이 모두 빈 줄은 무시한다.
- 사용 중인 품목만 신청할 수 있다. 화면에 품목별 가용을 보여 주고, 가용보다 많이 적어도 경고만 하고 제출을 허용한다(재고 확인은 승인 때).
- 임시저장은 없다. 제출하면 바로 '대기'다. 대기 중에는 고칠 수 없고 취소 후 다시 신청한다.
- 신청 당시 부서는 저장 후 바뀌지 않는다. 신청자가 부서를 옮겨도 승인자는 신청 당시 부서 기준으로 정한다.

### 상태

헤더: 대기(`PENDING`) / 반려(`REJECTED`) / 승인(`APPROVED`, 지급 대기) / 지급완료(`DELIVERED`) / 신청취소(`CANCELED`) / 지급취소(`DELIVERY_CANCELED`). 대기·승인에서만 다음 단계로 간다. 품목 결과: 미결 / 승인 / 반려.

| 전이 | 누가 | 조건과 결과 |
|---|---|---|
| 대기 → 승인 | 현재 승인자 | 승인 품목 1개 이상, 모든 승인 품목 가용 확인 통과 → 확보 |
| 대기 → 반려 | 현재 승인자 | 모든 품목 반려 → 재고 변화 없음 |
| 대기 → 신청취소 | 신청자 본인 | 재고 변화 없음 |
| 승인 → 지급완료 | 자산담당자 | 신청서 단위로 승인 품목 전부 한 번에 |
| 승인 → 지급취소 | 자산담당자 | 사유 필수, 확보분 복구(`RELEASE`) |

- 모든 상태 변경은 처리 이력(이전·이후 상태, 처리자, 사유, 시각)을 남긴다. 제출 행은 이전 상태가 비어 있다. 전체 반려의 처리 이력에는 사유가 비어 있고, 반려 사유는 품목마다 남는다.
- 이미 끝난 신청이나 다른 사람이 먼저 처리한 신청에 대한 처리는 "이미 처리된 신청입니다."로 거부한다.

### 승인자 결정

조회하거나 승인하는 그 시점에 정한다.
1. 신청 당시 부서에 지금 유효한 부서장이 있고 그 사람이 신청자가 아니면 → 그 부서장 한 명.
2. 아니면 → 신청자가 아닌, 로그인 가능한 관리자 전원.

- 제출 시점에 승인자가 한 명도 없으면 제출을 막는다(예: 부서장 없는 부서의 관리자가 신청했는데 다른 로그인 가능 관리자가 없음).
- 제출 후 승인자가 없어진 대기 신청은 관리자의 승인 대기함과 전체 신청 목록에 '승인자 없음'으로 보인다. 그래도 신청자 본인인 관리자는 승인할 수 없다.
- 유효한 부서장이 있으면 관리자는 그 신청의 승인자가 아니다.

### 승인

- 한 화면에서 품목마다 승인(수량 1 ≤ q ≤ 신청 수량) 또는 반려(사유 필수, 500자 이내)를 모두 정해 한 번에 제출한다. 미결 품목이 있으면 거부한다.
- 승인 품목 **전부**의 가용 ≥ 승인 수량이어야 한다. 하나라도 모자라면 아무것도 바꾸지 않고, 모자란 품목 전부를 "품목: 가용 a, 승인 q → n개 부족" 형식으로 알린다.
- 통과하면 한 트랜잭션에서 품목별 확보(`RESERVE`), 품목 결과, 헤더 상태(승인 또는 전체 반려면 반려), 승인자·승인 시각, 처리 이력을 기록한다.

### 지급

- 승인 상태 신청서만, 승인 품목 전부를 한 번에 지급한다. 반려된 품목은 지급하지 않는다.
- 개별 자산 품목은 그 품목의 보관 자산을 승인 수량과 **정확히 같은 대수**만큼 골라야 한다. 다른 품목의 자산, 보관이 아닌 자산, 중복 선택, 수량 비품에 자산을 고른 경우는 모두 거부한다.
- 고른 자산은 사용 상태가 되고 현재 사용자 = 신청자, 자산 이력에 신청번호가 남는다. 확보 수량은 지급 대수만큼 줄고 `DELIVER` 이력이 남는다. 수량 비품은 수량 변화가 없다.
- 지급 후에는 취소가 없다. 사용 자산을 돌려받는 것은 담당자의 반납 처리다.

### 조회 범위

| 사용자 | 볼 수 있는 신청 |
|---|---|
| 신청자 | 자기 신청 |
| 부서장(현재 유효) | 자기 부서(신청 당시 부서 기준)의 모든 상태 신청 |
| 자산담당자, 관리자 | 전체 |
| 현재 승인자 | 자기가 승인자인 대기 신청의 상세 |

부서장이 아닌 사용자가 부서 신청 조회를 열면 "부서장이 아닙니다"로 거부한다. 승인 대기함에는 지금 그 사용자가 승인자인 대기 신청만 나온다(관리자는 여기에 '승인자 없음' 신청이 더해진다).

## 동시 처리 결과

- 두 승인이 같은 품목을 동시에 확보해 합계가 가용을 넘으면 먼저 잠근 쪽만 성공하고, 가용은 0 미만이 되지 않는다.
- 승인과 신청취소가 동시에 오면 하나만 성공하고 늦은 쪽은 "이미 처리된 신청입니다."를 받는다.
- 같은 신청서를 두 번 승인·지급하면 한 번만 처리된다.
- 신청서 작성 화면의 더블클릭·새로고침 재전송은 1회용 제출 토큰으로 막아 신청서가 한 건만 생긴다. 토큰은 세션당 하나라서, 작성 화면을 두 탭에 열면 먼저 제출한 탭만 성공한다.
- 확보가 걸린 개별 자산은 수리·폐기로 빼돌릴 수 없다.

## 엑셀 일괄등록

- 품목 일괄등록: 한 줄 = 품목 1개(재고 0으로 시작). 필수: 품목명, 유형(수량/개별, 수량 비품/개별 자산도 허용). 분류코드·단위코드는 비워도 되지만 적으면 사용 중인 코드여야 한다. 최소 수량은 비우면 0, 음수·숫자 아님은 오류.
- 자산 일괄등록: 한 줄 = 자산 1대 입고. 필수: 품목코드, 자산번호. 품목은 사용 중인 개별 자산 유형이어야 한다.
- **한 줄이라도 틀리면 아무것도 저장하지 않는다.** 모든 줄을 먼저 검사해 틀린 줄의 엑셀 행 번호와 이유(필수값 누락, 코드 없음, 유형 불일치, 품목명 중복, 자산번호 중복 — 파일 안의 중복 포함)를 전부 보여 준다. 검사를 통과한 뒤 저장 중에 실패해도 전체를 되돌린다.
- 파일 안 중복은 대소문자를 무시하고 비교한다. 첫 행은 머리글로 보고 건너뛰며, 빈 행은 무시한다.

## 내려받기

- 재고 현황: 품목코드, 품목명, 유형, 분류, 단위, 재고 또는 보관 수(수량 비품은 재고, 개별 자산은 보관 수), 확보 수량, 가용, 최소 수량, 사용 여부.
- 자산 대장: 자산번호, 품목, 상태, 현재 사용자, 비고.
- 신청 내역: 신청일 기준 기간(양 끝 포함), 신청 품목 한 줄당 한 행 — 신청번호, 신청일, 신청자, 부서(신청 당시), 품목, 신청 수량, 승인 수량, 품목 결과, 헤더 상태, 승인자, 처리일.

## 야간 재고 부족 집계

- 대상: 사용 중이면서 `가용 < 최소 수량`인 품목. 가용 = 최소 수량이면 대상이 아니다. 부족분 = 최소 수량 − 가용.
- 매일 02:00(Asia/Seoul) 자동 실행(실행자 SYSTEM), 자산담당자는 화면에서 즉시 실행(실행자 = 그 담당자).
- 대상이 0건이어도 실행 기록은 남는다. 화면은 가장 최근 실행의 시각·구분·실행자와 품목 목록을 보여 준다.
- 실행마다 공통컴포넌트 배치 결과에 성공(정상) 또는 실패(비정상, 오류 내용) 한 행을 남긴다. 실패하면 그 실행의 집계 행은 남지 않는다.

## 초기 데이터(시연용)

- 부서 3개: 총무과(부서장 head1), 정보화팀(부서장 head2), 민원실(부서장 없음 → 관리자 대체 승인 시연).
- 관리자 2명(서로의 신청을 승인), 자산담당자 1명, 부서별 신청자.
- 수량 비품 5종, 개별 자산 3종(노트북 3·모니터 4·태블릿 2대). 프린터 토너와 태블릿은 가용이 최소 수량보다 적어 집계 결과에 나온다.
- 모든 초기 재고는 입고 이력과 함께 들어 있다.
