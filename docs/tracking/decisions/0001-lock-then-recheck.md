# 0001. 재고 동시 처리는 품목 행 잠금 후 재확인

## 배경
- 같은 품목을 여러 승인이 동시에 확보하면 가용이 음수가 될 수 있다.
- 이 시스템에는 두 종류의 수량이 있다. 수량 비품은 재고 수량 하나지만, 개별 자산의 가용은 "보관 자산 수 − 확보 수량"이라 두 테이블에 걸친다.
- 이 규칙은 승인만이 아니라 지급·취소·입고·조정·반납·수리·폐기·일괄등록 모두에 적용되어야 한다.

## 결정
재고·상태를 바꾸는 모든 처리는 한 가지 순서를 따른다.
1. 관련 신청서 행을 `FOR UPDATE`로 잠근다.
2. 관련 품목 행을 품목코드 오름차순으로 `FOR UPDATE` 잠근다.
3. 가용·상태를 다시 읽어 확인한다.
4. 바꾼다.

개별 자산의 보관 수는 잠금 아래에서 `FOR SHARE`로 읽는다.

## 대안
- **조건부 차감**(`UPDATE ... SET STOCK_QTY = STOCK_QTY - n WHERE STOCK_QTY >= n`, 영향 행 수로 판단): 수량 비품에는 간단하다. 그러나 개별 자산 가용은 다른 테이블의 행 수에 달려 있어 한 문장으로 표현할 수 없고, 여러 품목의 전부 또는 전무 판단과 "모자란 품목 전부 알리기"를 하려면 결국 먼저 읽어야 한다. 사용자가 거절했다.
- **낙관적 잠금**(버전 열): 충돌 시 재시도 로직과 사용자 재제출이 필요하다. 이 시스템 규모(수십 명)에서는 이득이 없다.

## 결과
- 품목 행이 직렬화 지점이다. 같은 품목을 다루는 처리는 차례로 실행된다. 수십 명 규모에서는 문제없지만, 인기 품목 하나에 요청이 몰리면 대기가 생긴다.
- 잠금 순서가 전 모듈의 규약이 된다. 신청서 → 품목(오름차순) → 자산 순서를 어기는 코드는 교착을 만든다. 품목을 잠그기 전에 자산 행을 바꿀 수 없다.
- 수량 비품과 개별 자산을 같은 방식으로 다루므로, 공공 SI에서 흔한 방식으로 설명할 수 있다.
