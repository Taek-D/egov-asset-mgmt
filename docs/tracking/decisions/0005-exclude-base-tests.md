# 0005. 공통컴포넌트 자체 테스트는 컴파일에서 제외

## 배경
- 기반 pom은 테스트를 고정값으로 건너뛰었지만 테스트 소스는 컴파일했다.
- 업무 통합 테스트는 루트 컨텍스트 전체(`egovframework` 컴포넌트 스캔)를 띄운다. 그러자 공통컴포넌트 테스트 소스의 `@Configuration` 클래스(`EgovCryptoTestConfig`)가 스캔되어 Crypto 설정을 기본 키로 덮어썼고, DB 접속이 실패했다.
- 공통컴포넌트 테스트의 상당수는 외부 DB 주소를 가리켜 이 환경에서 돌지 않는다.

## 결정
- 컴파일러 설정에 `testExcludes: egovframework/com/**`를 두어 공통컴포넌트 테스트를 컴파일하지 않는다.
- surefire `skipTests`는 속성으로 바꿔(기본 true) 검증 스크립트만 `-DskipTests=false`로 업무 테스트를 실행한다.

## 대안
- **업무 테스트 컨텍스트에서 스캔 필터로 제외**: 공통컴포넌트 설정 XML을 테스트용으로 따로 복제해야 하고, 운영과 다른 컨텍스트를 검증하게 된다.
- **문제 클래스만 삭제**: 기반 소스를 지우는 것이라 "통째로 가져와 최소한만 고친다"는 원칙에 어긋나고, 다른 테스트 설정이 같은 문제를 일으킬 수 있다.

## 결과
- 공통컴포넌트 테스트는 이 저장소에서 실행할 수 없다(검증 대상 아님).
- 테스트 컴파일 시간이 크게 줄었다.
- 공통컴포넌트 테스트 리소스(`src/test/resources`)는 여전히 클래스패스에 올라간다. 업무 테스트는 운영 설정 경로(`file:src/main/resources/...`)만 읽도록 되어 있다.
