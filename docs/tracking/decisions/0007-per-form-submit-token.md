# 0007. 신청서 제출 토큰은 화면별로 업무 쪽에서 관리

## 배경
1차에서는 신청서 작성 화면의 중복 제출 방지에 공통컴포넌트 `EgovDoubleSubmitHelper`를 그대로 썼다. 이 도우미는 세션에 토큰을 하나만 두고, 확인하자마자 새 토큰으로 바꾼다. 그 결과 작성 화면을 두 탭에 열면 먼저 제출한 탭만 성공했고, 규칙 위반으로 실패한 화면을 새로고침으로 다시 보내도 거부되었다.

## 결정
- 신청 컨트롤러가 화면마다 1회용 토큰(`assetReqToken`)을 발급해 세션에 보관한다. 최근 20개만 두고, 넘치면 오래된 것부터 버린다.
- 요청에 아직 쓰지 않은 토큰이 있으면 다시 그린 화면(줄 추가, 제출 실패)도 같은 토큰을 유지한다.
- 토큰은 신청서가 실제로 만들어졌을 때만 소모한다.
- 폼 렌더링과 제출은 세션 뮤텍스 안에서 한다. 제출은 서비스 호출이 끝날 때까지 뮤텍스를 잡는다. 같은 토큰의 동시 요청은 순서대로 처리되고, 앞 요청이 성공했으면 뒤 요청은 거부된다.

## 대안
- **공통컴포넌트 도우미 유지**: 세션당 토큰 1개라 두 탭과 실패 후 재전송을 풀 수 없다.
- **도우미 소스 수정**: 기반 소스 수정을 최소로 한다는 원칙에 어긋나고, 다른 공통컴포넌트 화면의 동작까지 바뀐다.
- **실패 때만 새 토큰으로 다시 그리기**: 새로고침 재전송은 옛 토큰을 보내므로 여전히 거부된다.

## 결과
- 두 탭은 각각 한 번씩 제출되고, 실패한 화면은 한 번 더 받아들여진다. 더블클릭은 신청서 한 건만 만든다.
- 제출이 끝날 때까지 같은 세션의 다른 제출·작성 화면 요청이 기다린다. 한 사용자 세션 안의 일이라 영향은 작다.
- 이 화면은 공통컴포넌트 이중 제출 태그를 더 쓰지 않는다. 다른 공통컴포넌트 화면은 그대로다.
