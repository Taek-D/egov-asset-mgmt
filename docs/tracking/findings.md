# 미해결 문제

## 야간 집계 테스트가 드물게 실패함(최근 실행 조회)

- 증상: 2차 통합 검증에서 한 번 `AssetShortageTest.zeroHitAutoRunIsStillRecorded`가 "가장 최근 실행"으로 자기 실행(`SHRT_…106`) 대신 앞선 실행(`SHRT_…102`)을 받아 실패했다. 같은 코드로 다시 돌리면 105건 모두 통과했다.
- 추정 원인: 최근 실행 조회가 `RUN_PNTTM DESC, RUN_ID DESC` 순이다. 실행 시각은 DB의 `SYSDATE()`로 초 단위다. Docker VM 시계가 뒤로 보정되면 뒤에 만든 실행의 시각이 앞 실행보다 이를 수 있다. 당시 여러 검증을 동시에 돌려 VM 부하가 컸다. 재현은 하지 못했다.
- 영향: 운영에서는 시계가 뒤로 가는 순간에만 화면의 "최근 실행"이 직전 실행으로 보일 수 있다. 집계 결과와 배치 결과 기록은 정상이다.
- 방안: 실행 ID가 생성 순서대로 커지므로 최근 실행 조회를 `RUN_ID DESC`만으로 정렬한다.

## 반려 사유 절단이 이모지 한가운데를 자를 수 있음

- 증상: 처리 이력 사유의 500자 절단은 Java 문자(UTF-16) 단위다. 품목명이나 사유에 이모지 같은 보조 문자가 있고 절단 위치가 그 중간이면 반쪽 문자가 남는다. DB에는 `?`로 저장될 수 있다.
- 영향: 이력 사유 끝 한 글자가 깨져 보인다. 길이 제한과 다른 데이터는 정상이다.
- 방안: 자를 위치가 서로게이트 쌍 가운데면 한 칸 앞에서 자른다.
